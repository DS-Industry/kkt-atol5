# kkt-atol5

Flask-сервис для печати фискальных чеков через ККТ АТОЛ (драйвер `libfptr10`). Работает на **Orange Pi** у кассы: принимает данные чека по HTTP от мойки / POS, ставит задачу в очередь и печатает чек на физическом регистраторе по USB или TCP.

Требования 54-ФЗ к порядку операций на ККТ соблюдаются в `CashierService`: открытие смены → чек → регистрация позиций → оплата → налог → итог → закрытие. При ошибке после открытия чека выполняется отмена (`cancelReceipt`), а не «тихий» успех.

## Что умеет

- Приём чеков: `POST /create-check` (заголовок `Data` с JSON — как у текущих клиентов мойки)
- Очередь в SQLite: `pending` → `printing` → `done` | `failed`
- Подключение к ККТ: **USB** или **TCP** (IP/порт драйвера, обычно `5555`)
- Настройки без правки кода: `instance/config.json` + веб-админка
- Таймауты на открытие смены и ожидание QR (без бесконечных циклов)
- Переподключение при обрыве связи (в т.ч. ошибка 4 / порт недоступен)
- Диагностика для поддержки: слой сбоя `APP` / `LINK` / `KKT` / `FN_OFD`
- Админ-интерфейс: статус, настройки, логи, список чеков
- QR-экраны Telemetron по TCP: количества постов, роботов и пылесосов,
  отдельные IP/порты и отправка фискального QR после успешного чека.
  Настройка `/admin/displays`, описание — [docs/qr-displays.md](docs/qr-displays.md).

Аутентификации на API и `/admin` **нет** — сервис рассчитан на доверенную LAN. Не выставляйте наружу без отдельной защиты.

## Архитектура

### Общая схема

```
┌─────────────┐     HTTP (LAN)      ┌──────────────────────────────────────┐
│  Клиент     │ ─────────────────► │  Orange Pi                           │
│  мойки/POS  │ ◄───────────────── │                                      │
└─────────────┘   QR / ошибка      │  ┌────────────┐   ┌───────────────┐ │
                                   │  │  Flask API │   │  Admin GUI    │ │
                                   │  │  /create-  │   │  /admin/*     │ │
                                   │  │  check     │   │               │ │
                                   │  └─────┬──────┘   └───────┬───────┘ │
                                   │        │                  │         │
                                   │        ▼                  ▼         │
                                   │  ┌────────────────────────────────┐ │
                                   │  │ SQLite (очередь Check)         │ │
                                   │  │ pending → printing → done|fail │ │
                                   │  └────────────────┬───────────────┘ │
                                   │                   │                 │
                                   │        APScheduler job1 (~3 с)      │
                                   │                   │                 │
                                   │                   ▼                 │
                                   │  ┌────────────────────────────────┐ │
                                   │  │ CashierService (+ RLock)       │ │
                                   │  │ смена, печать, reconnect,      │ │
                                   │  │ диагностика                    │ │
                                   │  └────────────────┬───────────────┘ │
                                   │                   │ libfptr10       │
                                   └───────────────────┼─────────────────┘
                                                       │ USB или TCP
                                                       ▼
                                              ┌─────────────────┐
                                              │     ККТ АТОЛ    │
                                              └────────┬────────┘
                                                       │ ОФД
                                                       ▼
                                              оператор фискальных данных
```

Один процесс ОС обслуживает и HTTP, и фоновую печать. Несколько worker’ов недопустимы: драйвер ККТ не рассчитан на параллельный доступ.

### Слои приложения

| Слой | Где | Ответственность |
|------|-----|-----------------|
| HTTP / GUI | `app/http/`, `templates/admin/` | Валидация входа, коды ответа, админка, постановка в очередь, ожидание QR |
| Очередь / состояние | `app/data/models.py` + SQLite | Жизненный цикл чека, причины сбоя, слой `layer` для поддержки |
| Планировщик | Flask-APScheduler `job1` | Берёт `pending`, печатает по одному, пишет `done`/`failed` |
| Фискальный сервис | `app/services/cashier.py` | Единственный доступ к устройству: open/reconnect, смена, чек, диагностика |
| Драйвер | `libfptr10.py` → native `.so` | Вендорный API АТОЛ (не править стиль файла) |
| Конфиг | `app/data/config.py` + `instance/config.json` | Режим USB/TCP, IP, таймауты, HTTP-порт, путь к библиотеке |
| Диагностика | `app/services/faults.py` | Маппинг кода ошибки → `APP` / `LINK` / `KKT` / `FN_OFD` |

Правило разделения: маршруты Flask **не** вызывают `IFptr` напрямую — только методы `CashierService`.

### Поток печати чека

1. Клиент шлёт `POST /create-check` (JSON в заголовке `Data`).
2. `main` валидирует поля, создаёт строку `Check` со статусом `pending`, отвечает после появления QR или по таймауту (ожидание по **id** чека, не по имени товара).
3. `job1` (интервал ~3 с, `max_instances=1`) забирает задачу → `printing`.
4. При необходимости открывает/закрывает смену через `CashierService` (с таймаутами).
5. `print_check` выполняет фискальную последовательность на ККТ.
6. Успех: QR и флаги успеха пишутся в БД, статус `done` (строка **не** удаляется).
7. Ошибка: статус `failed`, сохраняются `message` / `error_code` / `layer` / `step`; HTTP клиенту — соответствующий код (502/503/504…), не «успех».

```
create-check ──► Check(pending) ──► job1 ──► printing
                                              │
                         ┌────────────────────┼────────────────────┐
                         ▼                    ▼                    ▼
                    смена OK             print_check          сбой связи
                         │                    │                    │
                         │         open→register→pay→…→close       reconnect
                         │                    │                    │
                         │              QR + done              failed + layer
                         └────────────────────┴────────────────────┘
```

### Фискальная последовательность (нельзя переставлять)

```
openReceipt → registration (позиции) → payment → receiptTax → receiptTotal → closeReceipt
```

После каждого критичного вызова проверяется `errorCode()`. Если чек уже открыт и шаг упал — `cancelReceipt` (или закрытие документа по правилам драйвера). «Успех» наружу возможен только когда вся цепочка завершилась корректно.

Доступ к `fptr` сериализован `threading.RLock` внутри `CashierService`: параллельные HTTP-запросы и `job1` не ходят на устройство одновременно.

### Подключение к ККТ

При старте и при «Save & reconnect» сервис применяет **только** параметры связи:

- модель (auto), порт USB **или** TCP (IP + порт драйвера), канал ОФД auto;
- затем `applySingleSettings()` и `open()`.

Полная перезапись таблиц ОФД / Wi‑Fi / сетевых параметров устройства на каждый boot **не** делается (это отдельное provisioning, не runtime).

При `isOpened == 0` или ошибке «порт недоступен» (код 4) — переподключение с backoff.

### Очередь и данные

| Статус | Смысл |
|--------|--------|
| `pending` | В очереди, ещё не печатали |
| `printing` | `job1` взял задачу |
| `done` | Печать и QR успешны |
| `failed` | Ошибка; чек остаётся для разбора |

Исторические поля (`isProcessed`, `isQr`, опечатки вроде `quiantity`) сохранены как контракт с клиентами/БД. В истории хранится до 1000 чеков: удаляются только самые старые завершённые/ошибочные записи, а `pending`, `printing` и чеки с активным ожиданием QR защищены от очистки. В `/admin/checks` выводятся признак `QR generated`, дата/время по Москве и полный текст QR.

### Слои сбоя (для поддержки)

| Слой | Кто чинит | Пример |
|------|-----------|--------|
| `APP` | Наше ПО / Orange Pi | SQLite, валидация, процесс не отвечает |
| `LINK` | Кабель / USB / TCP / питание ККТ | Ошибка 4, устройство не открылось |
| `KKT` | Касса / смена / бумага | Команда на открытом устройстве не прошла |
| `FN_OFD` | ФН / ОФД | Код 123, переполнение ФН, обмен с ОФД |

Лестница `GET|POST /admin/diagnostics` идёт сверху вниз (приложение → библиотека → open → смена → ФН/ОФД), останавливается на первом провале и подсказывает следующий шаг.

### Конфиг в рантайме

```
DEFAULTS в app/data/config.py  ←  merge  ←  instance/config.json
                                      ↑
                            Admin → Settings (Save)
```

Смена режима USB/TCP или IP применяется через «Сохранить и переподключить» (или рестарт сервиса). HTTP host/port читаются при старте процесса.

Кассир на чеке настраивается в `Admin → Settings`: `cashier_name` (тег ФФД 1021,
до 64 символов) и необязательный `cashier_inn` (тег 1203, 12 цифр). Обычного
`Save` достаточно — новое значение применяется к следующему печатаемому чеку
через `operatorLogin()` до `openReceipt()`. Пустое имя сохраняет текущего
оператора ККТ без попытки определить или сбросить его из приложения.

Для ККТ, уже зарегистрированной в составе автоматических устройств, в
`Admin → Settings` включается `automatic_mode` и задаётся соответствие
`machine_numbers_by_bay` строками `ID_поста=заводской_номер`. Поле `bay`
входящего чека выбирает номер конкретного поста, который передаётся как тег
ФФД 1036 непосредственно перед `openReceipt()`. Если ID отсутствует в таблице,
фискальный документ не открывается. Программа не выставляет тег 1001: это
признак регистрации ККТ, а не настройка отдельного чека.

Там же выбирается налоговая ставка: **Без НДС**, **НДС 0%**, **5%**, **7%**,
**10%** или **22%**. По умолчанию используется «Без НДС». Ставка применяется
к следующему чеку после обычного `Save`, без переподключения. Для ставок
5%, 7% и 22% драйвер и прошивка ККТ должны поддерживать соответствующую ставку.

## Быстрый старт

### Зависимости

```bash
pip install -r requirements.txt
```

### Продакшен (Orange Pi + ККТ)

Нужны установленный драйвер АТОЛ и подключённая касса.

```bash
python3 main.py
```

По умолчанию слушает `0.0.0.0:5000` (см. `instance/config.json` / `app/data/config.py`).

На кассе процесс держит Supervisor. Имя программы на Orange Pi — `flesh`.
[`deploy/flesh.conf`](deploy/flesh.conf) — общий шаблон без путей конкретного устройства.
После создания `.venv` установите конфигурацию из папки проекта:

```bash
sudo python3 deploy/install_supervisor.py
sudo systemctl enable --now supervisor
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl status flesh
```

Установщик определяет расположение проекта по своему файлу и записывает реальные
пути в `/etc/supervisor/conf.d/flesh.conf`, вне Git. Запускать его можно из любой
папки, указав путь к скрипту. Для другого расположения проекта можно передать
`--project-dir /путь/к/kkt-atol5`. Шаблон вручную редактировать или копировать не нужно.
После переноса проекта повторите установку; `.venv` создайте заново на новом месте.
При обычном обновлении кода достаточно `git pull --ff-only` и
`sudo supervisorctl restart flesh`. Локальные настройки Supervisor меняйте в
`/etc/supervisor/conf.d/flesh.conf`; повторная установка заменяет этот файл шаблоном.

Список всех программ: `sudo supervisorctl status`. Перезапуск: `sudo supervisorctl restart flesh`.
Чеклист на железе: [`docs/hardware-smoke-checklist.md`](docs/hardware-smoke-checklist.md)  
Операционка (USB autosuspend, health, диагностика): [`docs/ops-runbook.md`](docs/ops-runbook.md)

На одном процессе должен крутиться и HTTP, и фоновая печать (`job1`). Не запускайте несколько worker’ов Gunicorn — они будут драться за ККТ.

### Разработка на Mac без драйвера

Без `libfptr10` обычный `python3 main.py` упадёт. Для GUI и API без железа:

```bash
MOCK_IFPTR=1 python3 main.py
```

Открыть: `http://127.0.0.1:5000/admin/status`.
`MOCK_IFPTR` не заменяет проверку реальной печати.

### Тесты (без ККТ)

```bash
pytest -q
```

Используется заглушка `FakeIFptr` (`tests/fake_fptr.py`).

## Админка

| URL | Назначение |
|-----|------------|
| `/admin/status` | Связь с ККТ, смена, очередь, слой сбоя, диагностика |
| `/admin/settings` | Кассир, налоговая ставка, USB/TCP, IP ККТ, таймауты, путь к библиотеке |
| `/admin/logs` | Хвост `atol.log` |
| `/admin/checks` | Недавние чеки и статусы |

В настройках IP — это **адрес драйвера** (Orange Pi → ККТ), не хост ОФД и не «Ethernet ККТ» из таблицы параметров устройства.

## Основные HTTP-эндпоинты

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/create-check` | Создать чек (JSON в заголовке `Data`) |
| `GET` | `/get-checks` | Список чеков (фильтр `?layer=` опционально) |
| `GET` | `/health` | Здоровье: БД + устройство + смена |
| `GET`/`POST` | `/admin/diagnostics` | Лестница диагностики (без продажи) |

При ошибках HTTP-код ответа совпадает с полем `code` в JSON (400 / 502 / 503 / 504 и т.д.).

## Документация

### QR-картинка для ПЛК/СПК

Успешный ответ `POST /create-check` теперь дополнительно содержит `qrImageUrl` —
полный HTTP-адрес PNG. Старое поле `qr` не меняется. ПЛК/СПК загружает картинку
обычным `GET` по этому адресу. В `GET /get-checks` поле также доступно для
успешных чеков с QR, для остальных равно `null`.

PNG содержит понятную подпись: название услуги/устройства из `name`, номер
`bay`, сумму, способ оплаты и дату чека. Сумма и время берутся из фискального
QR (при отсутствии суммы — из записи в БД), поэтому не зависят от часов Orange Pi.
Конкретная функция («пена», «воск» и т.п.) в текущем контракте не сохраняется
и на картинке не отображается. Схема БД этой доработкой не меняется.

Сам QR кодирует точно фискальную строку из ККТ. Подпись — пояснение к оплате,
не замена фискального чека. PNG имеет ширину не менее 600 пикселей и переменную
высоту. Отображайте целиком, с белыми полями, без обрезки. QR сохранён без
масштабирования (8 пикселей на модуль). Для картинки только с QR добавьте
`?plain=1` к `qrImageUrl`. Ответ имеет тип `image/png`.
Для кириллицы на Orange Pi требуется системный шрифт DejaVu Sans
(`/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` и `DejaVuSans-Bold.ttf`).

Ссылка формируется с адресом и портом входящего запроса: обращайтесь к Orange Pi
по доступному для ПЛК адресу, например `http://192.168.28.251:5000`.
Ссылка подписана, работает после перезапуска и пока исходный чек хранится в БД
(история до 10000 чеков). При удалении чека возвращается 404.
Файл `instance/qr-image.key` создаётся автоматически: сохраняйте его с резервной
копией БД, иначе старые ссылки перестанут работать. Не публикуйте сервер в
интернете: существующие административные/API-эндпоинты остаются без авторизации.

## Важно

- Смена должна быть `OPEN`; `EXPIRED` сначала закрывается отчётом, потом открывается новая.
- Успех печати — только после закрытия чека и получения QR (или явный `failed`).
- База при старте **не** очищается (`db.drop_all` убран).
- Типовые поля модели `Check` (`quiantity`, `isProcessed`, …) — исторический контракт; не переименовывать молча.
- Полевые сбои USB/ОФД/БП сначала смотрите в `docs/issues/issues.md`.

## Статус

Проект в активной доработке под production-stable (фазы A–D по FSD). Юнит-тесты с моком драйвера зелёные локально; финальная приёмка печати — только на Orange Pi с реальной ККТ.
